```c
#include "kernel/types.h"
#include "user.h"
void
f(void)
{
    int a[4];
    int *b = malloc(16);
    int *c;
    int i;

    printf("1: a = %p, b = %p, c \n", a, b);

    c = a;
    for (i = 0; i < 4; i++)
	    a[i] = 100 + i;
    c[0] = 200;
    printf("2: a[0] = %d, a[1] = %d, a[2] = %d, a[3] = %d\n",
	   a[0], a[1], a[2], a[3]);

    c[1] = 300;
    *(c + 2) = 301;
    3[c] = 302;
    printf("3: a[0] = %d, a[1] = %d, a[2] = %d, a[3] = %d\n",
	   a[0], a[1], a[2], a[3]);

    c = c + 1;
    *c = 400;
    printf("4: a[0] = %d, a[1] = %d, a[2] = %d, a[3] = %d\n",
	   a[0], a[1], a[2], a[3]);

    c = (int *) ((char *) c + 1);
    *c = 500;
    printf("5: a[0] = %d, a[1] = %d, a[2] = %d, a[3] = %d\n",
	   a[0], a[1], a[2], a[3]);

    b = (int *) a + 1;
    c = (int *) ((char *) a + 1);
    printf("6: a = %p, b = %p, c = %p\n", a, b, c);
}

int
main(int ac, char **av)
{
    f();
    return 0;
}
```
2:
c 指向数组 a 的首元素 &a[0]，此后 c 和 a 完全等价，c[i] 等价 a[i]。
赋值后：
a[0]=200，a[1]=101，a[2]=102，a[3]=103
3:
C 语言语法规则：arr[i] 等价于 *(arr+i)，加法交换律 i[arr] = *(i+arr)。
所以 3[c] = *(3 + c) 等价 c[3]，语法完全正确，没有错误，只是风格诡异。
执行后：
a[1]=300，a[2]=301，a[3]=302，此时数组：
[200, 300, 301, 302]

4:
指针运算是按指向类型步进，c 是 int*，c+1 向后偏移一个 int（4 字节），指向 a[1]。
*c=400 把 a[1] 修改为 400；
数组变为：[200, 400, 301, 302]

5:
当前 c 原本指向 a[1]（int*）；
强转 (char*)c：变成字节指针；+1 只向后移动 1 个字节；
现在指针落在 a[1] 内部第二个字节的位置，没有对齐到 int 4 字节边界；
强制转回 int*，对这个非对齐地址解引用赋值 *c=500。
`
a[1] 4字节：字节0、字节1、字节2、字节3
a[2] 4字节：字节0、字节1、字节2、字节3
`
指针卡在 a[1] 的第 2 个字节，写入 4 字节的 500，会向后侵占：
a[1]后半段 + a[2]前半段，两个整型的值全部被暴力篡改，数据彻底错乱。

6:
b = (int*)a +1：指向 a[1]，只是修改指针本身，没有读写内存；
c 指向 a 往后 1 字节的错位地址，只打印地址，不解引用，安全。
